# Release procedure

## Before

1. `cargo xtask ci` — fmt, check, clippy `-D warnings`, test, doc.
2. `cargo test --workspace` with a real Xray-core present, so the compiler and
   acceptance tests actually run rather than skipping.
3. `cargo xtask upstream-check`, and re-read `docs/UPSTREAM-COMPATIBILITY.md`.
   If the pinned Xray tag has moved, update the date, re-vendor the protobuf
   closure and re-run the compiler tests, which are what prove the generated
   configuration still loads.
4. Update `STATUS.md`. It must state what was actually run, in what environment,
   with real numbers. An unexecuted test is never recorded as passing.
5. Update `CHANGELOG.md`.
6. `cargo audit` and `cargo deny check`. Document any accepted advisory in
   `CHANGELOG.md` with the reason; never silence one quietly.

## Versioning

Semantic versioning on the user-visible surface: the CLI, the configuration
schema and the IPC protocol. Bumping `PROTOCOL_VERSION` or `SCHEMA_VERSION` is at
least a minor release, and a schema bump needs a migration in
`crates/config/src/migrate.rs` with a test.

## Cutting

```sh
# Bump workspace.package.version in Cargo.toml, then:
cargo build --release --workspace
cargo xtask install --prefix /usr --destdir /tmp/stage --dry-run
git commit -am "Release vX.Y.Z"
git tag -a vX.Y.Z -m "vX.Y.Z"
```

## Artifacts

* Source tarball.
* `packaging/arch/PKGBUILD` with the tarball's `sha256sum` filled in.
* Completions and man pages are generated by the binary during install, so they
  cannot drift from the command surface.

## After

Verify on a clean machine:

```sh
cargo build --release --workspace
sudo cargo xtask install --prefix /usr
systemctl --user enable --now xraytuid.service
xraytui doctor
```

Confirm that neither `xraytui`, `xraytuid` nor `xray` runs as root, and that no
installed file is setuid:

```sh
ps -o user,comm -C xraytui -C xraytuid -C xray
find /usr/bin -name 'xraytui*' -perm /6000    # expect no output
```
